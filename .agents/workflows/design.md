# /design — Design direction

> Optional. Use for a new, consequential, or recurring visual/interaction surface, or to extract scattered design knowledge.

1. **Ground.** Read root → target `AGENT.md` and `DESIGN.md` if present.
   Read relevant accepted specs/decisions plus real or representative content,
   states, platform, and constraints. Keep scope bounded; label assumptions.
2. **Route.** Preserve an accepted direction and make the smallest compatible
   change. If direction is open, ask only questions that change composition;
   compare 2–3 structurally different candidates with the same product truth.
   If knowledge is scattered, inventory it first; the route may change as
   answers clarify the project.
3. **Contract.** Record the selected or provisional thesis, domain anchor,
   system roles, signature, prohibitions, exceptions, rejected alternatives,
   and evidence in project-owned `DESIGN.md` (or its linked equivalent).
   `DESIGN.md` is optional; never create it merely to add ceremony, and never
   turn one project's style into a universal rule.
4. **Build.** Implement one coherent system using real or representative
   content. Every surface, line, shadow, effect, label, and component must earn
   its place through content, hierarchy, state, continuity, or interaction.
   Never invent metrics or filler content to decorate a composition.
5. **Review.** Render relevant widths and states, inspect the result, and
   obtain a user checkpoint before locking consequential taste or product
   meaning. Run applicable deterministic/accessibility checks and at least one
   revision. Use subject-swap, necessity, distinction, and continuity tests as
   diagnosis, not bans.
6. **Persist.** Put stable rules/examples in `DESIGN.md` or `docs/design/`,
   operational rules in the narrowest `AGENT.md`, and evidence/rejections in
   the task worklog. For extraction, copy/link by default, preserve history,
   show the source → destination map and conflicts, wait for approval, then
   write and run `/reconcile`.
7. **Close.** Report what is accepted, provisional, rejected, unverified, and
   open. Do not claim visual success without rendered observation, and do not
   mutate on answer-only or read-only requests.
