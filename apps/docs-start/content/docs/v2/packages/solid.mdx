```package-install
@solar-icons/solid
```

## Import patterns

```jsx
// Per-style (no style suffix - style in path)
import { HeartIcon } from '@solar-icons/solid/bold'

// Single icon
import { HeartIcon } from '@solar-icons/solid/bold/heart'

// Top-level (style suffix in name)
import { HeartBoldIcon } from '@solar-icons/solid'
```

## Basic usage

```jsx
import { HeartIcon } from '@solar-icons/solid/bold'

function App() {
    return <HeartIcon color="#ef4444" size={32} />
}
```

## Duotone

```jsx
import { HeartIcon } from '@solar-icons/solid/bold-duotone'

function App() {
    return <HeartIcon color="#3b82f6" secondaryColor="#f59e0b" secondaryOpacity={0.4} size={48} />
}
```

## Stroke width

```jsx
import { SettingsIcon } from '@solar-icons/solid/linear'

function App() {
    return <SettingsIcon strokeWidth={2} size={24} />
}
```

## SolarProvider

Uses Solid signals internally.

```jsx
import { SolarProvider } from '@solar-icons/solid'
import { HeartIcon } from '@solar-icons/solid/bold'

function App() {
    return (
        <SolarProvider color="#3b82f6" size={24} strokeWidth={1.5}>
            <HeartIcon />
        </SolarProvider>
    )
}
```

## useSolar

Returns Solid `Accessor`s. Must be called inside a `<SolarProvider>`.

```jsx
import { useSolar } from '@solar-icons/solid'

function ColorToggle() {
    const { color, setColor } = useSolar()

    return <button onClick={() => setColor('#ef4444')}>Current: {color()}</button>
}
```

## Icon props

| Prop               | Type               | Description            |
| ------------------ | ------------------ | ---------------------- |
| `color`            | `string`           | Icon color             |
| `size`             | `string \| number` | Width and height       |
| `strokeWidth`      | `string \| number` | Stroke width           |
| `secondaryColor`   | `string`           | Duotone accent color   |
| `secondaryOpacity` | `number`           | Duotone accent opacity |
| `isolated`         | `boolean`          | Ignores provider       |
| `alt`              | `string`           | Accessibility label    |

All standard SVG attributes pass through.

## CSS variables

Same as [React](/docs/v2/packages/react#css-variables).

## CSS classes

Every icon renders with class `solar` plus `solar-{name}-{style}`. See the [React page](/docs/v2/packages/react#css-classes).

## ESM only

`@solar-icons/solid` is ESM-only. `require()` does not work.

## Solid 2

`@solar-icons/solid` is for Solid 1. Solid 2 has its own package, `@solar-icons/solid-v2`:

```sh
npm install @solar-icons/solid-v2 solid-js@next @solidjs/web@next
```

The `v2` in the name is the Solid major version, not the Solar Icons one. Import paths, component names, props, CSS variables and CSS classes are the same, so only the package name changes in your imports:

```jsx
import { SolarProvider } from '@solar-icons/solid-v2'
import { HeartIcon } from '@solar-icons/solid-v2/bold'
```

Solid 1 and Solid 2 differ in their compiler output, runtimes (`solid-js/web` became `@solidjs/web`), reactivity rules and JSX types. One build cannot serve both without trade-offs in server rendering, hydration and typing, so the two packages exist side by side while the framework changes major version. This split is specific to Solid. We will look again at a single package once the Solid 2 ecosystem is mature, and `@solar-icons/solid` remains the package for Solid 1 and is not deprecated.

`@solar-icons/solid-v2` requires Solid 2 (`solid-js` and `@solidjs/web` `^2.0.0-rc.22`, currently a release candidate and tested with `rc.22`), and a JSX build for Solid 2 (`@solidjs/vite-plugin` 3 or `unplugin-solid` 3, with `"jsxImportSource": "@solidjs/web"`). The [package README](https://github.com/saoudi-h/solar-icons/tree/main/packages/solid-v2) lists the differences with the Solid 1 package.
