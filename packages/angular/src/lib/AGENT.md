# AGENT: packages/angular/src/lib

Scope: Hand-written Angular primitives (`icon-base.ts`, `solar-provider.ts`, `icon-registry.ts`, `dynamic-icon.component.ts`, `all-icons.types.ts`) and unit tests.

- **`icon-base.ts`:** Uses `input()` signals (NO defaults, so `undefined` falls through via `??` to CSS vars) and `computed()` signals. Host bindings use `[style.width]`, `[style.height]`, `[style.color]` (not `[attr.*]`) so `var()` works. `secondaryColor`/`secondaryOpacity` bind `[style.--solar-secondary-*]`. `aria-hidden="true"` is auto-set unless `alt`, `ariaLabel`, or `titleAttr` is set. `isolated` bypasses `SolarProvider` CSS vars (hardcodes `24px`, `currentColor`, `1.5`, and `initial` for duotone vars). `class: 'solar'` is set on generated static components, not on `IconBase`.
- **`solar-provider.ts`:** `SolarProvider` (`solar-provider`) wraps content in a `<div>` with CSS custom properties. Component-scoped `SolarService` exposes `setColor`, `setSize`, `setStrokeWidth`, `setDuotoneColor`, `setDuotoneOpacity`; `useSolar()` calls `inject(SolarService)` (must be called in injection context).
- **`useSolar()` race condition (B-3):** A projected child calling `useSolar().setColor(...)` in its `constructor` is overridden when `SolarProvider`'s `effect()` for `color="..."` runs afterwards (`solar-provider.spec.ts` pins this). Initialize state in `ngOnInit` or event handlers, not constructors.
- **`all-icons.types.ts`:** Generated by `scripts/generate-assets.ts` on a single line (`allNames.join(' | ')`). Do not manually reformat to multi-line.
- **Test pitfalls:** `fixture.nativeElement` is a wrapper `<div>`; target the host SVG via `fixture.nativeElement.querySelector('svg[solarArrowUp]')`. In jsdom, `SVGElement.classList` is `SVGAnimatedString`, not `DOMTokenList` — assert via `getAttribute('class')?.split(/\s+/).filter(Boolean)` (`dynamic-smoke.spec.ts`).
